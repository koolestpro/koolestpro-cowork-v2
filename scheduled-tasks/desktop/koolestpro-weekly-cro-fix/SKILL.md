- **Build the whole rebuild above the fold, no dead/wasted space** — if there's empty space below the last element (e.g. a guarantee line), shift things up and use that room for the product image instead of leaving it blank.
- **Logo and any brand asset: use the target's real file, never recreate it (2026-09-04, hard rule — see CLAUDE.md's "REAL BRAND ASSETS ONLY — NEVER RECREATE A LOGO" section).** Before writing the rebuild's DeepSeek task spec, locate the target's actual logo on their live site — the header `<img>`'s real `src`/`srcset` is the reliable source, not a guessed favicon path or a stale schema.org `logo` field, which can point to a different/lower-res variant. Download that real file and embed it exactly as it is (base64, per this project's export-compatibility rules) — resize, crop, or background-remove it if needed, but never redraw it as CSS text, shapes, or an approximate recreation, even when the real file is awkward to work with. **This applies just as much to text-based/wordmark logos as icon-style ones (2026-09-04, Ridwan's clarification)** — a lot of business logos are just the name set in a distinctive custom typeface, and that typeface IS the brand identity. It is essentially never one of the fonts already loaded on the page or available on Google Fonts, so retyping the brand name in a similar-looking web font and calling it the logo is exactly the recreation this rule bans — it reads as close-but-wrong, which is a worse tell than an icon mismatch since text is what people read first. Treat every logo as an image asset regardless of whether it's icon-based or text-based: download the real PNG/SVG and embed it as a real `<img>`, never as live HTML/CSS text. This applies to any other brand mark too (badges, seals, trust icons) — same rule. Include the real logo download as an explicit step in the DeepSeek task spec's NOTES section so it isn't left to guesswork. If the real logo genuinely can't be retrieved (dead link, blocked, or the live site is text-only with no logo file), say so plainly in the run summary rather than inventing one silently — a text-only real header is a fact worth carrying into the rebuild as-is. A rebuild with a subtly-wrong recreated logo undermines the entire "this is genuinely your page, fixed" CRO Fix pitch.
- **Image aspect-ratio integrity (2026-09-04 -> corrected 2026-09-07, hard rule).** Before using `object-fit:cover` on any container that composites a real screenshot or product photo, check the container's actual rendered aspect ratio against the source image's real aspect ratio. A Caraway run shipped `object-fit:cover` on a `flex:1` container whose aspect ratio (~0.89:1) was nowhere close to the source photo's (~1.16:1), which hard-cropped/zoomed the photo and read as "not the same image." If the ratios don't reasonably match, use `object-fit:contain` on a contrasting-background plinth (reads as deliberate premium framing, not empty space) or resize the container to actually match the image. Never ship a cover-fit container you haven't checked this way — verify on the real rendered export, not the markup.
- **Page-type labeling, everywhere (2026-09-07, hard rule).** Every `#ba-graphic` and `#anno-graphic` PNG must carry a visible page-type badge near the headline (e.g. "PRODUCT PAGE (PDP)", "HOMEPAGE", "LANDING PAGE (LP)") — a real rendered element, not a code comment. Every carousel slide with an eyebrow tag (cover, evidence slides) gets a second badge stating the page type. Every caption (LinkedIn, Instagram, X angles, X thread, and the social-content library entries) states the page type explicitly, ideally in the opening line. Use the real audited page type — never default to PDP if it was something else.
- **Full-space carousels with redundant labeling (2026-09-07, hard rule).** No carousel slide may end with a large empty/plain-background band. Any slide built around a state/label (Myth, Reality, The Pattern, Before, After) must bake that label into something large (a 20px+ pill badge with the actual word, not just a 9-12px eyebrow tag) in addition to the small tag — the small tag alone can vanish under platform compression or a fast scroll, so the concept must not depend on it surviving. When a slide embeds a full-bleed evidence image meant to fill remaining space, verify on the actual export that it does — `flex:1` outside a real flex-column ancestor does nothing, and this exact bug shipped once (Caraway evidence slides). Also check every slide's page-counter/handle overlay for legibility against whatever is actually behind it — give it a semi-opaque backdrop chip so it never depends on a dark background being there.
- **Contextual, non-generic icons or imagery for empty carousel space (2026-09-07, hard rule).** When a slide needs a supporting visual, it must be specific to that slide's actual finding — pull real SVG icons from Iconify's public API (`https://api.iconify.design/{prefix}/{icon}.svg?color=%23HEX`, no key needed) that name the specific thing (a star for a reviews/trust point, a price tag for a pricing fix, a numbered-list icon for a repeatable pattern), inlined as real markup at both a large low-opacity watermark size and a small colored badge size for visual consistency. Never use a generic decorative shape or an icon that could apply to any post.
- **CTA slide avatar must be Ridwan's real Cloudinary photo, never an empty placeholder (2026-09-07).** A CTA slide with a blank/empty avatar div shipped once (Caraway) — always use the real hosted URL from CLAUDE.md's "RIDWAN'S BRAND PHOTOS (CLOUDINARY — MANDATORY)" section, with the existing `onerror` fallback pattern.

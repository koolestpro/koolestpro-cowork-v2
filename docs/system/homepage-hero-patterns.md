# Homepage hero patterns (CRO Fix, homepage rebuilds) 2026-10-11

Ridwan, on the Bala homepage rebuild: research before building the hero, never narrow a
multi-category brand to one product, and no long left-aligned text block on the mobile hero.
Research + reference board: `references-for-posts/homepage-hero-research-2026-10-11/`.

## The pattern (from 8 reference before/afters + live captures + Baymard/Instant)

1. **Image first, ~45-50% of the screen, product-forward.** The product or the range is
   identifiable at a glance. For a multi-category brand, show the range (a kit/flatlay or a
   range shot), not one hero SKU.
2. **Labels/badges on the image carry the facts** (product names, key stats, an award), so the
   copy under it stays short.
3. **Centered stack, short:** proof line (stars + real count, say what the count covers) →
   H1, 2 lines, says the category in plain words, can keep the brand's voice → one-line sub.
4. **One full-width primary CTA**, category-led ("Shop best sellers", "Shop Greens").
5. **Then the way in + trust:** category pills, press logos or 2-3 trust icons.
6. No carousel, one announcement bar max, no variant picker or buy box (that's a PDP).

## Process

- Build 3-4 directions from the families (image top + stack / text first + band / full-bleed
  scrim) on the brand's real assets, put them on one board, pick one and write why
  (`CHOICE.md`). Keep the runner-up as an A/B challenger.
- Check every photo for things the shopper can't buy (sold-out collabs) before using it.

## Variants are mandatory, every CRO Fix (2026-10-11)

Homepage or PDP, every run builds 3-4 hero variants and a board. The board is also a post: it goes out on X before the carousel as a neutral "which would you ship?" debate. See `docs/system/variants-board-post.md`.

## Step 1 — Extract the core

Read the raw input. Ask internally:
- What is the real tension or problem this idea addresses?
- Who is specifically affected?
- What is the most surprising or counterintuitive angle on this?
- What framework or Big Idea connects to this?

## Step 2 — Run the SUCCESs lens

Apply the Made to Stick SUCCESs framework to find the sharpest possible angle. This is not optional — every idea must pass through all six lenses before any content is written.

**S — Simple:** What is the single commander's intent of this idea? If someone remembers ONE thing from this carousel, what must it be? Strip everything else. Express it in one sentence, as if explaining to someone who has never thought about this before.

**U — Unexpected:** What is the counterintuitive or pattern-breaking angle? What would surprise someone who thinks they already know about this topic? Find the gap between what people believe and what is actually true. This becomes the cover hook and the myth/problem slide.

**C — Concrete:** Replace every abstraction with a specific, sensory, picturable detail. "Faster" → exact time saved. "Better results" → specific percentage or metric. "Lots of clients" → exact number. "Common mistake" → the exact mistake with a name. Use before/after numbers wherever possible.

**C — Credible:** What is the Sinatra Test for this topic? One stat, one result, one example so specific that it handles all doubt. The stat slide exists for this. Find a real, specific number — not vague claims.

**E — Emotional:** Find the one person's frustration, not the category's problem. Not "developers waste time" — "you open your builder, start guessing, rebuild the same section three times, show the client a half-built page, and still wonder why it feels wrong." Make the reader feel recognised.

**S — Stories:** Build a story arc across the full carousel — not just a list of tips. Structure: character (the reader in their current situation) → problem (the real tension) → false attempts (the wrong ways they've tried) → the shift (the core insight) → resolution (the transformation) → new world (what life looks like after).

**SUCCESs score the hook:** Rate the cover headline you've chosen 1–10 on each dimension. If any dimension is below 7, rewrite it. Don't proceed until the hook scores ≥7 on Simple, Unexpected, and Emotional simultaneously.

## Step 3 — Make all decisions

**PILLAR** → pick the closest of the 3 pillars

**SLIDE COUNT** → default to **7**. Use 6 only for a single sharp point. Use 8-10 only for a deep framework or case study that genuinely needs more space. Less is always better. The cover and CTA are always included. Filler slides are never acceptable — every slide must earn its place. (7 is the default because it measurably outperforms other lengths for this format — do not pad a 6-slide idea up to 7 just to hit the number.)

**FORMAT** → default to a **Myth vs Reality / contrarian-diagnostic angle** ("you think X, actually Y") — this drives comments through polarization and cognitive dissonance. Fall back to a **framework/methodology** carousel (walking through one of Ridwan's named frameworks) when the topic genuinely has no myth to bust — that format drives saves instead of comments, still strong but a different lever. Both beat a generic "here are some tips" list.

**HAS BEFORE/AFTER** → true for redesigns, audits, case studies, visual transformations. False for conceptual/framework topics.

**CTA** → based on topic:
- CRO, product pages, conversion → `DM me "AUDIT" →`
- Design process, dev workflow, Figma → `DM me "BUILD" →`
- Freelancing, personal brand, growth → `DM me "GROW" →`
- Personal story, Builder's Journey → `Follow @koolestpro for more`

**GRAPHIC TYPE** → pick for each of the 3 Section-2 variations:
- Variation A: Editorial typographic (quote dominates, minimal everything else)
- Variation B: Stat/Data card (the key number or metric fills the frame)
- Variation C: Atmospheric (glow-heavy, cinematic, mood-driven)

**VISUAL TREATMENT** (mandatory decision, see full system below) → pick the dominant visual anchor for the cover and decide which content slides get an icon-badge or screenshot accent. Never default to the same combination two carousels in a row — before deciding, glance at whatever Tips carousel was shipped most recently in `outputs/tips/` and deliberately choose something visually different for this one, especially the cover.

**HOOK** → from the SUCCESs lens. Must be specific, bold, slightly provocative. Leads with reader's pain or a counterintuitive claim. NOT a topic title.

**PULL QUOTE** → from Ridwan's Big Ideas list or written in his voice. One sentence that could stand alone as a tweet.

# ════════════════════════════════════════════
# VISUAL ANCHOR & VARIETY SYSTEM (mandatory — read before building any slide)
# ════════════════════════════════════════════

Carousels went through a density pass: every slide is now **headline-only + micro anchor** — one bold headline or statement per slide, at most one short subline (~15-20 words), no bullet stacks, no multi-sentence paragraphs. That fixed the text-density problem. It did not, by itself, fix visual sameness — a carousel that's all headline-only typography with the same glow-blob-in-the-corner treatment every time just trades one boring pattern for another. This section exists so that doesn't happen. Every carousel must look considered, not templated.

### The cover always gets a supporting visual

The cover slide is what shows up as the thumbnail on both LinkedIn and Instagram — it can never be pure typography. It must carry a real visual element sized to dominate the frame (roughly 35-45% of the slide's height), with the avatar, name/role, eyebrow, and headline sitting underneath as a secondary layer. Text on the cover stays minimal: headline plus at most one short line, nothing more.

### Real photo vs. custom visual — the actual decision rule

Do not default to "a real photo is more credible" or to "a custom graphic is safer/cheaper." The right choice depends entirely on what the slide is claiming:

- **Use a real screenshot** (of an actual Ridwan-built page, a real client rebuild, or a genuine product UI) when the slide's point is literally about one specific, concrete UI pattern — the image itself IS the evidence for the claim. Screenshot the real page (or crop an existing one), upload to Cloudinary, embed the hosted URL. Never a local file path — local paths break the html2canvas export pipeline.
- **Use a custom-built visual** (CSS/HTML shapes, inline SVG, an Iconify icon) when the slide's point is conceptual or metaphorical. A real-but-thematically-irrelevant stock photo is worse than a tightly relevant built visual — a photo that isn't actually evidence of anything just looks like decoration wearing a costume of authenticity. Build something that visually represents the actual idea instead.

If you're not sure which bucket a slide falls into, ask: "if someone questioned this slide, would pointing at the photo settle the argument?" If yes, it's real-screenshot territory. If the photo would just be sitting there looking nice, it's custom-visual territory.

### Treatment menu — rotate across carousels, mix within one

Pick from (or invent a sibling of) these per carousel. The point isn't to use all six every time — it's to make sure two consecutive carousels don't lean on the same one or two treatments back to back:

1. **Motion/Ghost Trail** — a stack of overlapping shapes fading from solid to near-transparent along a path (e.g. a button "ghosting" itself). Good for topics about excess motion, repetition, momentum, or "too much of something."
2. **Icon Badge Accents** — small circular badges (~40-44px, brand-orange stroke, translucent orange fill, 1px border) holding a single Iconify icon, placed opposite a slide's eyebrow tag/label. One relevant icon per slide it's used on — pick the icon for what that specific slide claims, not generically.
3. **Real Screenshot Proof** — a Cloudinary-hosted crop of an actual built page or product, reserved for slides making a literal UI-pattern claim (see decision rule above).
4. **Stat/Numeral Hero** — one giant stat number as the dominant visual. Solid `#FF9500`, never gradient text (see Gradient Rules below).
5. **Geometric/Abstract Composition** — custom inline SVG shapes (grids, overlapping circles, paths, rules) built to represent the concept without literal imagery. Good when neither a real screenshot nor an obvious icon fits.
6. **Real-world Photo Support** (Pexels/Pixabay) — for when a literal real-world object or scene needs representing and no real screenshot of Ridwan's own work exists. Crop and color-treat to sit inside the dark brand palette rather than dropping in an untreated stock photo as-is.

**Asset sources, confirmed available:**
- **Iconify** — `https://api.iconify.design/{prefix}/{icon}.svg?color=%23FF9500&width=N`, no API key required, 200+ open icon sets (lucide is a good default — thin-stroke style matches this brand). Fetch the SVG once and inline the raw `<path>`/`<circle>` markup directly into the HTML rather than hotlinking the URL, so exports don't depend on live network reachability at capture time.
- **Pexels** (`PEXELS_API_KEY`) and **Pixabay** (`PIXABAY_API_KEY`) — both live in this project's `.env` files, same keys the `stock-footage` skill uses.

### No em dashes, anywhere

Scan every headline, subline, and caption for "—" before treating it as final. Rewrite as two sentences, a comma, or a colon instead. This applies to every piece of generated copy, not just slide text.

# PHASE 2 — OUTPUT: FULL HTML FILE
# ════════════════════════════════════════════

Output one complete, self-contained HTML file. No placeholders. Every slide fully written and coded.

**How the file actually gets built:** don't generate the HTML freehand from scratch each time. The reliable, proven method is a region-swap: start from the most recently approved Tips carousel file (same JS, same CSS, same capture functions, byte-for-byte), and only swap the slide content strings (headlines, sublines, visual blocks) for the new topic. Freeform generation of the full JS/CSS from memory tends to drift on geometry and capture behavior — reusing a known-good file's mechanics and changing only content is what keeps every output structurally correct.

### Type Scale — HARD FLOOR, never go below

| Role | Size | Notes |
|---|---|---|
| Cover headline | 30–42px | Syne 800 |
| Slide heading / statement | 30–42px | Syne 800, statement slides may go larger |
| Primary body prose | **15px minimum**, line-height 1.7 | DM Mono is correct for body — the typeface was never the problem |
| Secondary/nested body (labels, chips, footnotes) | **13px minimum** | never below |
| Big stat number | 96–120px | Syne 800, solid `#FF9500` |
| Slide footer / attribution credit | 12px | |
| Eyebrow / section labels | 9–12px **only if** uppercase + letter-spacing | the sole exception to the 13px floor |

Nothing inside a slide goes below 12px unless it's an uppercase tracking label. If a slide's content stops more than ~15% short of the bottom edge, the layout is wrong — give the content container `flex:1` with `justify-content:space-evenly` (list slides) or `center` (statement slides) so it fills the frame. Check this on the rendered PNG, not in the markup.

### Text color — solid colors only, no gradient text anywhere

❌ Never use CSS `background-clip: text` — invisible in html2canvas exports.



## SLIDE SEQUENCE — 7-slide default (Myth vs Reality format)

Every slide must pass this test: **if this slide were removed, would the carousel be weaker?** If not, cut it. Every slide is headline-only + micro anchor — one bold statement, at most one ~15-20 word subline, a visual anchor per the system above.

| # | Type | Content focus | Typical visual anchor |
|---|---|---|---|
| 1 | Cover | Hook headline (SUCCESs: Unexpected + Simple), avatar + name/role, minimal subline | Dominant custom or real visual, ~40% of frame height |
| 2 | The Myth | One headline stating what people wrongly believe | Icon badge opposite the "THE MYTH" tag |
| 3 | Stat / Proof | One giant stat number + short label + 1-line context | Stat/Numeral Hero, or real screenshot if the stat is about a literal UI outcome |
| 4 | The Reality | One headline stating the contrarian truth | Icon badge opposite the "THE REALITY" tag |
| 5 | How it shows up | Concretely ground the reality — 2-3 short labels or one real screenshot | Real Screenshot Proof when there's a literal UI pattern to show; short bold labels with `flex:1;justify-content:space-evenly` otherwise |
| 6 | The Question / Filter | One incisive framing question + one-line answer | Icon badge opposite the eyebrow label |
| 7 | CTA | Avatar, bold CTA question, gradient button, save prompt | Avatar-led, per existing CTA pattern |

**6-slide variant (single sharp point):** drop slide 5, fold its concrete grounding into slide 4's subline.
**Framework fallback (topic has no real myth to bust):** replace slides 2/4/6 with three sequential framework steps (still headline-only, still one icon/visual anchor each), keep cover/stat/CTA as-is.
**8-10 slide variant (deep framework or case study):** only when the topic genuinely needs the space — add slides between 5 and 6, never pad the ending.

## CONTENT RULES — RIDWAN'S VOICE

**Density (headline-only + micro anchor — this is the whole format, not a suggestion):**
- Cover: headline + at most 1 short subline + supporting visual
- Every content slide: ONE bold headline/statement, at most one micro-subline (~15-20 words) — never a bullet stack, never a multi-sentence paragraph
- Stat slide: number + short label + at most 1 line of context
- If a slide feels text-heavy, cut it in half, then cut it again

**Tone rules:**
- One idea per slide. If there are two ideas, make two slides or cut one.
- First sentence of any copy: bold, specific, no warm-up
- Numbers over adjectives: "3× faster" not "much faster"
- Named specifics over categories: "Shopify Liquid" not "your code"
- "You" not "businesses" — speak to one person
- Never: "In today's world...", "More and more...", "It's important to..."
- Never an em dash, anywhere — comma, colon, or a second sentence instead

## POST COPY — 5 TABS

### Optional named frameworks for Tab 1 / Tab 2 (added 2026-07-30)

Tab 1 (LinkedIn Long-form) and Tab 2 (LinkedIn Hook Post) default to the free-form structure described below, and that stays the default. When a topic clearly fits one of these named frameworks better, structure the copy around it explicitly instead — these are proven LinkedIn structures, not a replacement for Ridwan's voice:

- **PAS** — Problem → Agitation → Solution. Good for CRO/conversion topics where the reader is already half-aware of the problem.
- **AIDA** — Attention → Interest → Desire → Action. Good for a new framework/product-style reveal.
- **BAB** — Before → After → Bridge. Good for redesign/case-study topics, pairs naturally with a has-before/after carousel.
- **STAR** — Situation → Task → Action → Result. Good for Builder's Journey/client-work stories.
- **SLAY** — Story → Lesson → Actionable advice → You. Good for a personal/vulnerable Builder's Journey post.

Note which framework (if any) was used in the Phase 3 summary. Free-form (no named framework) remains perfectly valid — don't force a framework onto a topic that doesn't need one.

### Mobile-formatting tightening (added 2026-07-30, applies to Tab 1 and Tab 2)

These sharpen the existing "150-250 words, plain text, real line breaks" rule below with concrete, testable constraints:

- A blank line after every line — nothing reads as a dense block on mobile.
- Most lines: one sentence, roughly 55 characters or fewer.
- Up to 4 lines may be short mini-paragraphs (2-3 sentences, roughly 110 characters or fewer) — the rest stay single-sentence.
- Rule of Three: at most two trios (three-item lists/parallel structures) per post — more than that starts to feel formulaic.
- Vary how sentences start — don't let more than 2-3 lines in a row start with "I".
- Grade-6 words. No adverbs, no jargon, no filler.

### CTA pattern option: "Repost if" close (added 2026-07-30)

In addition to the existing CTA-by-topic table above, a tested close for Tab 1/Tab 2 specifically (not the carousel's own gradient-button CTA, which stays as-is) is ending on 2-3 lines that lock in the lesson, then a line reading "Repost if [this helped / you agree / you needed this]" — plain text, no emoji, this is a LinkedIn-native engagement pattern distinct from the DM-me CTAs. Use it when the post is a save/share-worthy insight rather than a lead-gen ask; don't use both CTA styles in the same post.

- Line 1: cover hook, exact same wording as carousel cover

```javascript
const track=document.getElementById('track'),vp=document.getElementById('viewport'),dotsEl=document.getElementById('dots'),pager=document.getElementById('pager');

vp.addEventListener('touchmove',e=>{if(!dragging)return;track.style.transform=`translateX(${-cur*W+e.touches[0].clientX-startX}px)`;},{passive:true});
```

## SLIDE CAPTURE + DOWNLOAD JAVASCRIPT (required — corrected geometry/capture, do not use scale:4/downsample)

⚠️ CRITICAL QUALITY RULES — never deviate from this pattern:
- Slides are **540×680px portrait**, captured at **`scale:2`** directly — no downsample step, the 2160×1360 canvas IS the deliverable
- Chrome-hiding is mandatory: `[data-chrome], #download-panel, .posts-shell, .swb, .section-label, .section-divider, .gcard-wrap` hidden via `visibility:'hidden'` (never `display:'none'`, which shifts layout) inside a try/finally
- Save and restore `track.style.transform`/`transition` around each capture
- Wait for fonts/images (`document.fonts.ready` + a short settle) and double `requestAnimationFrame` before calling html2canvas
- `backgroundColor:'#080808'`, `useCORS:true`, `allowTaint:true`, `logging:false`

```javascript
// ── CAROUSEL CAPTURE (540×680 portrait, scale:2) ─────────────────────────────
async function captureSlide(idx) {
  const slides = document.querySelectorAll('.slide');
  const slide = slides[idx];
  const toHide = document.querySelectorAll('[data-chrome], #download-panel, .posts-shell, .swb, .section-label, .section-divider, .gcard-wrap');
  toHide.forEach(el => el.style.visibility = 'hidden');
  const prevTransform = track.style.transform;
  const prevTransition = track.style.transition;
  track.style.transform = `translateX(-${idx * 540}px)`;
  track.style.transition = 'none';
  try {
    await document.fonts.ready;
    await new Promise(r => setTimeout(r, 300));
    await new Promise(r => requestAnimationFrame(() => requestAnimationFrame(r)));
    return await html2canvas(slide, { scale: 2, useCORS: true, allowTaint: true, backgroundColor: '#080808', logging: false });
  } finally {
    track.style.transform = prevTransform;
    track.style.transition = prevTransition;
    toHide.forEach(el => el.style.visibility = '');
  }
}

// ── GRAPHIC CARD CAPTURE (Section 2, 540×540, still scale:4+downsample to 1080 — different asset, unaffected by the carousel geometry fix) ──
async function captureCard(id){
  const card=document.getElementById(id);
  await document.fonts.ready;
  const raw=await html2canvas(card,{scale:4,useCORS:true,allowTaint:true,width:540,height:540,backgroundColor:'#080808',logging:false,imageTimeout:8000});
  const out=document.createElement('canvas');
  out.width=1080;out.height=1080;
  const ctx=out.getContext('2d');
  ctx.imageSmoothingEnabled=true;ctx.imageSmoothingQuality='high';
  ctx.drawImage(raw,0,0,1080,1080);
  return out;
}
// ── DOWNLOAD TRIGGER (CRITICAL — works in all browsers) ─────────────────────
// NEVER use bare a.click() without appending to DOM — silent failure in Safari/Chrome

  const a=document.createElement('a');
  a.href=href;a.download=filename;
  document.body.appendChild(a);a.click();document.body.removeChild(a);
}
async function dlSlide(i){const c=await captureSlide(i);triggerDownload(c.toDataURL('image/png'),`slide_${i+1}.png`);}

}
```

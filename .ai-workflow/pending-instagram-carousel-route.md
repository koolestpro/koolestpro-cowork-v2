# Instagram carousel route — build guide for the Make UI

Ridwan's call (2026-09-08): build this directly in the Make UI on the live "Koolestpro
Social Distribution" scenario (id 6565331), inside the existing Instagram router (the
module right after the platform router filters on Instagram — currently has 2 routes:
image and video/Reel). This avoids the wholesale blueprint-replace risk of doing it via
Claude's `scenarios_update` tool (see "Why not do this via API" at the bottom).

Follow this in order. Every URL/field below was read directly off the live, working
modules 301-303 (the single-image route) — this is the same pattern, extended to loop
over multiple images.

## Step 0 — before touching anything

Open scenario 6565331 in the Make editor and find the Instagram router (the small router
icon right after the module that filters `platform = Instagram`). It currently branches
into 2 routes. You're adding a **3rd route**.

## Step 1 — add the 3rd route, with the right filter

Click the router, add a new route. Set its filter:

- **Label:** `carousel`
- **Condition:** `asset_urls` **Contains** `; ` (semicolon + space — that's the exact
  separator the queue uses to join multiple image URLs)

## Step 2 — tighten the EXISTING image route's filter (module 301) — do not skip this

Module 301 currently matches if `asset_urls` ends with `.png` OR `.jpg` OR `.jpeg`. A
multi-image row's `asset_urls` string ALSO ends with one of those (the last URL in the
list), so without this fix, a carousel row would fire down BOTH routes and post twice.

Open module 301's filter. For **each of the 3 existing rows** (ends with `.png`, ends
with `.jpg`, ends with `.jpeg`), click "Add AND" and add:

- `asset_urls` **Does not contain** `; `

So each of the 3 OR-rows becomes an AND pair: `(ends with .png) AND (does not contain "; ")`,
same for `.jpg` and `.jpeg`. This makes the two routes mutually exclusive.

## Step 3 — Iterator (splits the URL list into one bundle per image)

Add a Make **Iterator** module (search "Iterator" in the module picker) right after the
new route's filter.

- **Array:** `{{split(asset_urls; "; ")}}` — this splits the semicolon-joined string back
  into a real array, one image URL per bundle downstream.

## Step 4 — HTTP: create each child (carousel item) container

Add an **HTTP > Make a request** module right after the Iterator.

- **URL:** `https://graph.instagram.com/v20.0/{{2.instagram_business_account_id}}/media`
- **Method:** POST
- **Body type:** Application/x-www-form-urlencoded
- **Fields:**
  - `image_url` → the Iterator's output value (the current item from Step 3)
  - `is_carousel_item` → `true`
  - `access_token` → `{{2.instagram_page_access_token}}`
- No `caption` field here — captions only go on the parent container in Step 6, never on
  individual child containers (Meta rejects/ignores captions on children anyway).

This runs once per image, same as module 301 runs once per row — except now it's once
per image inside one row.

## Step 5 — Array Aggregator (collects the child container ids back into one list)

Add a Make **Array aggregator** module right after the HTTP module from Step 4.

- **Source module:** the HTTP module from Step 4
- **Target structure:** custom — add one field, key `id`, value = that HTTP module's
  `data.id` from its response (this is the created child container's id, same field
  module 301's response already gives you as `{{301.data.id}}` — same shape here)

This closes the iterator loop. Downstream of the aggregator, you're back to one bundle
per original row (not per image), which is what you want for the next steps.

## Step 6 — HTTP: create the parent carousel container

Add another **HTTP > Make a request** module after the aggregator.

- **URL:** `https://graph.instagram.com/v20.0/{{2.instagram_business_account_id}}/media`
- **Method:** POST
- **Body type:** Application/x-www-form-urlencoded
- **Fields:**
  - `media_type` → `CAROUSEL`
  - `children` → `{{join(map(<aggregator>.array; "id"); ",")}}` (replace `<aggregator>`
    with that module's actual number once it's in the scenario — Make's function panel
    will let you pick `map()` and `join()` from the Array functions list, and pick the
    aggregator's array as the source; this comma-joins all the child ids Meta needs)
  - `caption` → `{{1.\`14\`}}` (same caption field module 301 already uses — check this
    still points at the right column, since the exact `{{1.\`14\`}}` reference is
    generated by Make itself when you map the "caption" field from the Google Sheets
    trigger, don't hand-type the column number)
  - `access_token` → `{{2.instagram_page_access_token}}`

## Step 7 — Sleep

Add a **Tools > Sleep** module, duration **30** seconds — mirrors the existing sleep
(module 407) that gives Instagram time to process the container before publishing.

## Step 8 — HTTP: publish

Add another **HTTP > Make a request** module.

- **URL:** `https://graph.instagram.com/v20.0/{{2.instagram_business_account_id}}/media_publish`
- **Method:** POST
- **Body type:** Application/x-www-form-urlencoded
- **Fields:**
  - `creation_id` → the parent container HTTP module's (Step 6) `data.id`
  - `access_token` → `{{2.instagram_page_access_token}}`

## Step 9 — Google Sheets: mark Posted

Add a **Google Sheets > Update a Row** module, using the SAME existing Google Sheets
connection already used by module 303.

- **Spreadsheet:** `1I5SrLnwAfVV5260Y_nAytio49gh-NKmJeJdFXH3nqzg`
- **Sheet:** `Untitled`
- **Row number:** `{{1.__ROW_NUMBER__}}`
- **Column 10 (status):** `Posted`
- **Column 12 (posted_at):** `{{formatDate(now; "YYYY-MM-DD HH:mm")}}`

This is identical to module 303 — just recreate it the same way (or clone module 303 and
drag the clone into this new route, then it's already configured correctly).

## Why not do this via Claude's Make API tool instead

`scenarios_update` (the only edit tool available) wholesale-replaces the ENTIRE blueprint
— there's no partial-patch option. The full blueprint covers Twitter, LinkedIn, Instagram,
AND Facebook in one ~90KB/3,389-line document. Applying this change that way would mean
hand-transcribing the entire blueprint into one tool call with only this route added — a
single transcription error anywhere in those 3,389 lines (a dropped comma, a mistyped id)
risks breaking Twitter, LinkedIn, or Facebook posting too, not just Instagram. Confirmed
live this session: Claude's shell sandbox can't even read the saved blueprint file to
script a safe automated splice (different filesystem from where the file actually lives),
so there's no safer semi-automated path available either. Building it directly in the
Make UI, module by module, is genuinely the lower-risk path — Make validates each field
as you go, and nothing about the other 3 platforms' branches is ever touched.
